# M4 Squad strategy - standing rules for the Boot Room

User-owned rules the engine applies to every review. Set 12 Sep 2026. These are permanent until the user changes them; the weekly review flow reads this file before writing verdicts.

## 1. The goalkeeper punt rule

A deliberately non-starting goalkeeper in the XI is an intended auto-sub play, never a "confirm team news" flag.

- **Floor:** if the punt keeper does not play, the backup auto-subs in per FPL rules. The downside is covered by design.
- **Upside:** the punt keeper's rare starts have historically been strong in favourable fixtures (user's read, accepted as a standing premise).
- **When to flag keeper risk:** only when the BACKUP keeper's minutes are in doubt (injury, rotation threat, new signing). The starter being a doubt is the plan, not a problem.

Origin: user instruction 12 Sep 2026 - "Steele starts as he is almost certainly a non starter, so Kinsky will get subbed in by default. Bake this into the model so I do not get asked this every week."

## 2. The 10-second rule (review style)

Every review leads with the recommended moves - a short numbered list, one line each, action-first ("Start X", "Captain: Y", "Make 0 transfers"). The analysis layers below are supporting evidence, not the deliverable. If a reader cannot find the week's actions in 10 seconds, the review has failed.

Origin: user instruction 12 Sep 2026 - "Actionable items must be findable in 10 seconds."

## 3. Verdict format - A-B comparisons

Every contested call presents as an A-B comparison, not a paragraph.

- **Stacked cards:** Player A over Player B, never side-by-side (side-by-side dies at 390px). Identical dial order on both cards (price, points, ppm, consistency, fixture) so the eye compares vertically.
- **One shared verdict bar** beneath the pair: names the winner and the ONE stat that decided it ("decided by consistency: 1.000 vs 0.333"). Caveats ride on the player's note line, not in the verdict.
- **In-chat answers** follow the same shape: two compact lines plus verdict.
- **Outcome loop:** every call carries an outcome field, filled after the gameweek - held or busted, with the actual points each side returned. Busted calls feed the model log the same way retired signals do.

Origin: user steering 12 Sep 2026.
